# 예결위 서면질의서 작성

예산 분석이 끝난 내용을 **예결위 서면질의 양식 HWPX 에 서식 그대로** 채우는 문서 작성 전용 스킬이다. 사업을 새로 찾거나 수치를 분석하지 않는다. 내용은 사용자나 예산 분석기 결과에서 받는다.

## 준비물

- kordoc (CLI). `scripts/build.py` 가 환경변수 `KORDOC_CMD` → `~/.claude/skills/kordoc/engine/env.json` → PATH 의 `kordoc` → `npx -y kordoc` 순서로 찾는다.
- Python 3.10+ (표준 라이브러리만).
- 견본: `assets/template_2027.hwpx` (2027년도 예산안 서면질의 양식, 안내문·별첨을 뺀 5쪽본).

## 순서

1. **내용 받기.** 대상부처(1개), 상임위, 의원·정당·회차·제출일, 사업별 감액/증액 내용을 확인한다. 예산 분석기 결과가 있으면 거기서 사업명·코드·금액·사유를 그대로 옮긴다. 수치를 새로 만들거나 추정하지 않는다. 빠진 항목은 묻는다(샘플이면 홍길동·가나다당처럼 가상 값을 쓰고 그렇게 알린다).
2. **spec.json 쓰기.** [입력 규격](references/spec.md)을 따른다. 핵심 규칙:
   - 요구증감액은 **증감분만**(감액은 음수 → △). 반영 후 금액을 쓰지 않는다.
   - 증액은 세부사업만, 감액은 내역사업(`sub`)도 가능.
   - 기금은 2026년 당초·수정(7월말)과 2027년 계획안을 따로 넣는다.
   - 수정이유는 짧게 2~3줄, 개조식 `~임/~필요`.
3. **빌드.**
   ```bash
   python3 <스킬>/scripts/build.py spec.json 출력.hwpx
   ```
   build.py 가 하는 일: 1차 패치(감액 표 첫 행) → 칸 안 작성안내 상자·단 설정 삭제 → 2차 패치(모든 행) → 목록 빈 행·칸 안 빈 줄 삭제, 내역사업 강조 서식 정리 → `kordoc validate` + `check.py`.
4. **점검 결과 확인.** `점검 통과`가 나와야 한다. 실패하면 메시지대로 spec 을 고쳐 다시 빌드한다. 필요하면 kordoc 으로 결과를 다시 파싱해 내용을 눈으로 확인한다.
5. **전달.** 파일 경로와 함께 아래를 알린다.
   - 사용한 수치의 출처(예산 분석기 결과·원문 쪽)는 사용자가 준 그대로라는 점
   - kordoc 렌더러는 이 양식을 열지 못하므로 **화면 배치는 한글에서 확인**해야 한다는 점
   - HY신명조·HY중고딕이 없는 PC에서는 대체 글꼴로 보이지만 파일 속 글꼴 이름은 견본 그대로라는 점

## 결과 문서 모양

- 신청서·목록·내용 3쪽 구성(쪽 나눔은 견본 그대로).
- 목록: 질의 건수만큼 행, 남는 견본 행은 삭제.
- 내용: □ 총괄표 → ① 일반회계/특별회계(감액·증액) → ② 기금(감액·증액) → ③ 부대의견(안)·정책질의. 질의가 없는 칸은 `해당 없음`.
- 견본의 표 주석, 기금 ※ 작성기준, 요구증감액 작성예시 표는 남긴다. 감액 칸 안의 작성안내 음영 상자(‘글로벌 매칭형’ 예시)는 지운다.
- 글꼴·글자 서식은 견본 것만 쓴다(header.xml 동일).

## 직접 고칠 때 (스크립트 하나씩)

```bash
python3 scripts/make_markdown.py spec.json --stage 2 > edited.md   # 편집 마크다운 보기
python3 scripts/postprocess.py patched.hwpx out.hwpx                  # 후처리만
python3 scripts/check.py out.hwpx                                     # 점검만
```

## 견본이 바뀌었을 때 (다음 연도 양식 등)

- 새 견본을 kordoc 으로 `keep_layout_tables` 파싱해 표 구조를 확인한다.
- `make_markdown.py` 의 골격 문구(안내 상자 `GUIDE_*`, 참고표, 주석 문구, 연도)를 새 견본 문구와 똑같이 맞춘다. patch 는 문구가 같은 자리를 찾아 바꾸므로 한 글자라도 다르면 편집이 빠진다.
- `postprocess.py` 의 `GEN_IDS`·`FUND_IDS`·`GEN_PARA`·`FUND_PARA`(내역사업 줄 글자·문단 서식 번호)를 새 견본의 ‘내역사업인’ 견본 줄에서 다시 읽어 넣는다.
- `assets/` 에 새 견본을 넣고 `check.py` 에 `--template` 으로 넘긴다.

## kordoc 만으로 안 되는 것 (스크립트가 대신 하는 이유)

| 막힌 점 | 처리 |
| --- | --- |
| 칸 안에 중첩표·단 설정이 있는 행은 행 추가·삭제 거부 | 1차 패치 후 안내 상자·칸 안 1단 단 설정을 지우고 2차 패치 |
| 칸 안 줄 수를 줄이면 빈 문단이 남음 | 가장 안쪽 칸에서 빈 문단 삭제 |
| 견본 줄의 글자 서식 칸에 새 문장이 엉뚱하게 나뉘어 들어감(굵게 번짐) | ‘내역사업인’ 줄을 견본 서식 칸 구성으로 다시 나눔 |
| 렌더러가 이 견본을 열지 못함 | 재파싱·구조 검증·글꼴 정의 대조로 대신 점검, 화면은 한글에서 확인 |
