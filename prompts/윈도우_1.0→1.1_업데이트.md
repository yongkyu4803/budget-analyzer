# 예산분석기(윈도우 키트) 1.0 → 1.1 업데이트 프롬프트

이미 `kordoc-budget-windows-x64` 1.0.0 키트를 쓰고 있는 사람이 아래 프롬프트를 Claude Code·Codex 같은 코딩 에이전트에 붙여넣는다.
`[zip 경로]`는 받은 `kordoc-budget-windows-x64-1.1.0.zip`의 실제 경로로 바꾼다. 기존 키트 위치를 알면 `[기존 키트 경로]`도 바꾸고, 모르면 그대로 둔다.

---

예산분석기 윈도우 키트를 1.1.0으로 업데이트해줘.
새 패키지: [zip 경로]
기존 키트: [기존 키트 경로]

배경: 1.0.0에 들어 있는 kordoc 4.22.13은 HWP의 본문 구역이 100개를 넘거나 한 구역의 레코드가 50만 개를 넘으면 나머지를 경고 없이 버린다. 그래서 큰 예산 사업설명자료의 뒤쪽 사업이 Markdown에서 빠지고, `budget.cmd build`가 `오류: (719, 777)`처럼 사업 수가 맞지 않아 멈춘다. 1.1.0은 동봉 kordoc의 이 상한을 올려 두었다.

순서대로 해줘.

1. **기존 키트 찾기.** 기존 키트 경로가 주어지지 않았으면 `START-HERE.txt`의 첫 줄이 `… / 배포본 1.0.0`인 폴더를 찾는다(예: `C:\kordoc-kit`). 찾지 못하면 멈추고 물어본다. `%USERPROFILE%\.claude\skills`와 `%USERPROFILE%\.codex\skills`에서 `portable-kit.json`이 있는 `kordoc`·`budget-index`·`budget-search` 스킬도 찾아 `kit_root` 값을 적어 둔다.
2. **새 키트 풀기.** zip을 기존 키트 옆의 새 폴더에 푼다(예: `C:\kordoc-kit-1.1`). 기존 키트 폴더에 덮어 풀지 않는다. 경로는 짧게 둔다. 같은 폴더에 `.zip.sha256`이 있으면 zip의 SHA-256과 대조한다.
3. **점검.** 새 키트 폴더로 이동해 `check.cmd`를 실행한다(PowerShell이면 `.\check.cmd`). 종료 코드 0, 출력의 `"ok": true`, `"kit_version": "1.1.0"`, `"kordoc_hwp_limits": "sections 2000, records 5e6"`, `"test_mode": "windows-bundled-runtime"`을 확인한다. 실패하면 멈추고 출력을 보여준다.
4. **설치된 스킬 연결 바꾸기.** 1단계에서 찾은 스킬마다 `portable-kit.json`을 `portable-kit.json.bak-1.0`으로 복사해 둔 뒤 `kit_root`를 새 키트 경로로 고친다. 스킬의 다른 파일은 1.0.0과 같으므로 바꾸지 않는다. 설치된 스킬이 없으면 이 단계는 건너뛴다.
5. **기존 변환본 다시 만들기.** 1.0.0으로 변환한 Markdown은 잘렸을 수 있다. 내가 쓰던 예산 작업 폴더(`.budget-index\config.json`이 있는 폴더)를 찾아 목록을 보여주고, 어느 것을 다시 만들지 물어본다. 고른 폴더마다:
   - 기존 폴더는 그대로 두고 옆에 새 작업 폴더를 만든다(예: `원래이름-v1.1`).
   - 기존 폴더의 원본 HWP/HWPX와 `.budget-index\config.json`을 새 폴더로 **복사**한다. `facts.json`이 있으면 복사하지 말고 있다고만 알려준다(새 원문에 맞춰 다시 검토해야 한다).
   - 새 키트의 `convert.cmd "새 폴더"`로 변환한다(이미지 없이). 크기 한도 오류가 나면 `--max-unzip-mb 1024`를 붙여 다시 한다.
   - `budget.cmd --root "새 폴더" build`와 `budget.cmd --root "새 폴더" verify --originals`를 실행한다.
   - 사업 수가 설정의 `expected_programs`와 맞는지, 기존 폴더의 `budget.cmd --root "기존 폴더" verify` 결과(색인이 있었다면)보다 몇 개 늘었는지 알려준다.
6. **보고.** 새 키트 경로, 점검 결과, 바꾼 `portable-kit.json`과 백업 위치, 다시 만든 작업 폴더와 사업 수를 실제 출력에 근거해 한국어로 짧게 알려준다. 기존 키트 폴더는 지우지 말고, 확인이 끝나면 내가 직접 지울 수 있다고만 알려준다.

지키기: 기존 키트·작업 폴더·색인·원본 파일을 지우거나 덮어쓰지 않는다. Python·Node를 설치하거나 npm·pip·git·npx로 내려받지 않고 새 키트의 `.cmd`만 쓴다. 금액이나 사업 수를 추측하지 않는다. 실패하면 멈추고 원인과 출력을 보여준다.
